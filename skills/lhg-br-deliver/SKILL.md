# lhg-br-deliver：报告交付

> 目标：把洞察清单变成"读者愿意看完、看完知道怎么做"的报告。
> 核心纪律：**结论先行；大纲经用户确认后才生成正文；图表必须诚实**。
>
> **复用声明**：本 skill 的大纲方法论复用 lhg-plugs 组织自有插件 `lhg-ppt` 的
> `lhg-ppt-outline`（金字塔大纲：结论先行→MECE 分论点→每页一句话标题）。
> 要生成 PPT 页面时，页面构建细节走 `lhg-ppt` 的 `lhg-ppt-build`；
> 本 skill 只规定"商业报告"的内容组织与诚实标准。

## 1. 何时使用

- `/lhg-biz-report:biz-report` 第 4 步 → 全流程
- 洞察清单用户已确认 → 开始写报告
- 用户丢来一篇"数字堆砌版"初稿 → 按第 3 节重搭大纲
- 报告要转成 PPT → 大纲确认后走 lhg-ppt 方法论生成页面

## 2. 输入与输出

- **输入**：洞察清单（lhg-br-insight 输出，用户已确认）
- **输出**：报告大纲（用户确认）→ 图文报告（report.md）或 PPT
- **不输出**：新的洞察——写报告时发现缺数据，打回 lhg-br-insight，不许现编

## 3. 报告大纲（复用金字塔，结论先行）

```
核心结论（一句话）：Q3 营收稳步增长，线上渠道成为主力
├── 分论点 1：增长动能恢复（同比 +20%，环比 +9.1%）
├── 分论点 2：结构优化（线上占比 40%→60%）
├── 分论点 3：风险提示（线下增速放缓）
└── 下一步：三个行动
```

规则：

- 每节标题是一句**完整观点**，不是"数据""分析"这种空词
- 每节 ≤3 个要点，每个要点带数据
- 大纲给用户确认后再写正文——大纲错了，页面越漂亮返工越惨

## 4. 图表诚实守则

1. **纵轴从 0 开始**，除非标注"纵轴截断"（审计脚本 CHART-SCALE-001 会查）
2. **饼图加起来 =100%**，分类不超过 6 个，多了用条形图
3. **图标题写观点**，不写"营收趋势图"这种白开水——写"营收连续两季度加速"
4. **每个图在正文被引用**（"见图 1"），画了没人提的图删掉
5. **图的数据 = 源数据**：图表值必须能在 data.csv 找到出处（CHART-MATCH-001）
6. **单位标在图上**，不许让读者猜纵轴是元还是万元

### 图表选型速查

| 想表达 | 用什么图 | 不用什么 |
|---|---|---|
| 趋势（随时间变化） | 折线图 | 饼图（看不出趋势） |
| 结构（谁占多少） | 条形图（>6 类）/饼图（≤6 类） | 折线图 |
| 对比（A vs B） | 分组条形图 | 双饼图（没法比） |
| 分布 | 直方图 | 饼图 |

一图只讲一件事：一张图里同时讲趋势和结构，读者哪个都记不住。

### 报告篇幅控制

- 图文报告：正文 ≤10 页（含图），超了就砍 P2 洞察
- 执行摘要：≤半页，三个数字 + 一句结论，多了没人看
- 附录：P2 洞察、原始大表、口径变更记录全放附录，不许挤正文
- PPT 版：≤15 页，一页一观点，字数 ≤50 字/页——超了就是把报告念一遍

记住：报告是给忙人看的，短是美德。

### 写报告时的"三不许"

1. 不许现编数据：写报告时发现缺数，打回 lhg-br-insight，不许编一个"大概"
2. 不许改口径：正文里的"营收"必须和 metrics.json 的定义一字不差
3. 不许藏来源：每个章节的数据都要能追溯到 data.csv 的列，藏着掖着等于心虚

违反任何一条，打回重写——报告一旦外发，收回来的成本是重写的十倍。

### 大纲确认 checklist（发给用户前自查）

- [ ] 核心结论一句话能说清吗
- [ ] 分论点之间 MECE（不重不漏）吗
- [ ] 每节都有数据支撑吗
- [ ] 风险与口径说明都安排了位置吗
- [ ] 图表清单列好了吗（每个图都有标题、数据来源、引用位置）

大纲确认后，正文只是体力活；大纲没确认，正文写得越多返工越惨。

## 5. 报告结构清单（图文报告版）

1. 核心结论（开头，≤5 行）
2. 执行摘要（三个关键数字）
3. 分论点章节（每节：观点标题 + 数据 + 图表）
4. 风险与局限（只报喜不报忧的报告没人信第二次）
5. 口径说明（指标定义、统计周期、数据来源）
6. 下一步建议（行动项，写清谁、做什么、什么时候）

## 6. 人工评审清单（脚本之后必过）

脚本（report_audit.py）抓得到"对不对"，抓不到"好不好"。下面这些必须人眼过：

- [ ] 30 秒测试：打开报告 30 秒，能说出核心结论吗？
- [ ] 数字抽查：随手挑 3 个数字，能在 data.csv 找到出处吗？
- [ ] 图表诚实：第 4 节六条逐项过
- [ ] 口径一致：报告里的"营收"和 metrics.json 的定义是同一个吗？
- [ ] 没有"因为所以"乱因果（见 lhg-br-insight 第 6 节第 4 条）
- [ ] 下一步建议可执行（有主语、有动作、有时间）

## 7. 反模式

1. **大纲跳过**：直接写正文——写到一半发现逻辑不通，重写三遍
2. **标题党**：标题写观点，写成"震惊！营收暴涨"——观点标题不是标题党，是把结论前置
3. **图表装饰**：3D 饼图、渐变柱状图——花哨的图都在妨碍阅读
4. **风险藏起来**：把风险提示放在附录小字——第一次翻车就没人信了
5. **PPT = 报告截图**：把报告文字原样粘进 PPT——PPT 是讲稿的提词器，不是报告的翻版

## 8. 自检与反馈

### 质检门（报告交付前自查）

- [ ] 大纲用户已确认
- [ ] `report_audit.py` 的 STRUCT-* 与 CHART-* 全绿
- [ ] 第 6 节人工评审清单全勾
- [ ] 对外发送前 hook 校验通过

### 标准冒烟用例

1. 报告前 15 行无结论 → STRUCT-CONC-001 blocker，打回重写开头
2. 图表值与源数据对不上 → CHART-MATCH-001 blocker，修数据或修图

### 反馈

发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-biz-report/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。

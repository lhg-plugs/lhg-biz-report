# lhg-br-intake：商业数据接入与清洗

> 目标：把"用户丢过来的表"变成"可分析的干净数据 + 数据字典"。
> 核心纪律：**先诊断后动手，先备份后改数，口径问题先登记不许悄悄改**。
>
> **复用声明**：本 skill 的清洗方法论复用 lhg-plugs 组织自有插件 `lhg-excel` 的
> `lhg-ex-clean`（表格数据清洗五步法）与 `lhg-ex-opslog`（操作日志规范）。
> 细节（判定口径、常见坑）以那两个 skill 为准，本 skill 只规定"分析流程"
> 需要的输入输出契约。

## 1. 何时使用

- `/lhg-biz-report:biz-report` 第 1 步 → 全流程
- 用户丢来一个表格说"帮我分析一下" → 先跑本 skill，再进 lhg-br-metric
- 只想知道表有多脏、暂不动手 → 只跑第 2 步（诊断）

## 2. 输入与输出

- **输入**：原始表格/CSV（xlsx / xls / CSV），+ 用户一句话"想分析什么"
- **输出**：
  1. 干净数据（`data.csv`：第一行为表头、无合并单元格、无 junk 行）
  2. 数据字典（`data_dictionary.md`：每列的含义、单位、口径、空值率）
  3. 口径问题登记表（清洗中发现的"定义不明"项，转交 lhg-br-metric）
- **不输出**：指标定义（那是 lhg-br-metric 的事）、分析结论（那是 lhg-br-insight 的事）

## 3. 分步方法论

### 第 1 步：备份（改前必做）

原文件复制一份到 `.bak/`（带时间戳），路径告诉用户。
无备份的清洗 = 不许发生。

### 第 2 步：诊断（动手前必做，输出诊断卡）

按 `lhg-ex-clean` 第 2 步的 7 问出诊断卡，**另加分析视角 3 问**：

1. **时间列**：有没有 period/日期列？粒度是天/周/月/季度？缺失的时间段有哪些？
2. **可比性**：要对比的各期，口径一致吗？（Q1 含税、Q3 不含税这种坑在这里抓）
3. **颗粒度**：数据能拆到渠道/产品/区域吗？拆不了，洞察阶段的"结构拆解"就做不了——提前告诉用户

诊断卡给用户确认后再动手。

### 第 3 步：清洗（按 lhg-ex-clean 五步法）

诊断→去重→类型统一→空值处理→junk 行清理。
每一步记操作日志（复用 `lhg-ex-opslog` 格式）。

**分析流程特有规则**：

- 合计行：源表里的"合计"行要删掉（分析时自己算），但删之前核对"合计=分项和"，对不上→记为口径问题
- 口径存疑的列：不许"看着像就改"，原样保留 + 登记到口径问题表
- 单位混杂列（如"万/元"混写）：统一成一种，换算过程记日志

### 第 4 步：输出数据字典

```markdown
| 列名 | 含义 | 单位 | 口径/备注 | 空值率 |
|---|---|---|---|---|
| revenue | 主营业务收入 | 万元 | 含税，财务系统导出 | 0% |
```

### 第 5 步：口径问题登记表

```markdown
| # | 问题 | 涉及列 | 建议口径 | 状态 |
|---|---|---|---|---|
| 1 | Q1 营收是否含税不明 | revenue | 待用户确认 | 待确认 |
```

这张表是 lhg-br-metric 的输入。

### 诊断卡模板（第 2 步输出示例）

```markdown
文件：sales_q3.xlsx（1.2 万行 × 18 列，1 个 sheet）
- 表头：第 1 行是表头，无合并单元格
- 空值：退款金额列空值率 35%（建议保留并标注"无退款"）
- 重复：订单号重复 12 条（需去重）
- 类型混杂：金额列混有"—"（3 处，拟按空值处理）
- junk：末尾 2 行"合计"行（拟删除，删除前核对合计=分项和）
- 时间列：month 列，2026-01 至 2026-09，缺 2026-02（需标注）
- 口径存疑：Q1 金额是否含税不明 → 记入口径问题表
```

诊断卡发给用户确认后再动手，确认方式可以是一句"可以"。

### 清洗常见坑速查（第 3 步执行时对照）

| 坑 | 症状 | 处理 |
|---|---|---|
| 日期格式混杂 | 2026/1/1 与 2026-01-01 并存 | 统一成 YYYY-MM-DD |
| 全角半角混杂 | "ＡＢＣ"与"ABC"并存 | 统一半角 |
| 不可见字符 | 看着一样但匹配不上 | 去首尾空白与零宽字符 |
| 科学计数法 | 长订单号变成 1.23E+15 | 设为文本列重导 |
| 合计行参与计算 | 透视结果翻倍 | 删合计行（删前先核对） |
| 表头跨行 | 读出来全是空列名 | 手动指定表头行 |

坑处理完，在操作日志里记一笔"坑→处理"，方便复查。

清洗的终点不是"表好看了"，而是"第 4 步的数据字典能写出来"——写不出来，
说明还有没搞清楚的列，回去继续。

数据字典写完，自己读一遍：外行能看懂每列是什么意思吗？看不懂就重写备注。
字典是给三个月后的自己看的，现在省一句，将来猜半天。

## 4. 反模式

1. **跳过诊断直接洗**："表看着挺干净"——然后同比算出来是错的，因为 Q1 口径不一样
2. **悄悄改数**：把"—"改成 0 不记日志——0 和"无数据"是两回事，改了要留痕
3. **合计行不删**：带着合计行做透视，合计被重复计算
4. **口径问题自己猜**："应该含税吧"——猜的口径会在报告里变成"事实"，翻车时找不到源头
5. **清洗完不输出字典**：三个月后回看，不知道每列当初是什么意思

## 5. 自检与反馈

### 质检门（数据交付前自查）

- [ ] 原文件已备份，路径已告知用户
- [ ] 诊断卡用户已确认
- [ ] `data.csv` 无合并单元格、无 junk 行、表头唯一
- [ ] 数据字典完整，口径问题表无"已猜未确认"项
- [ ] 操作日志完整（改了什么、为什么改）

### 标准冒烟用例

1. 表头上方有 2 行标题 + 中间有"合计"行 → 诊断卡标出，清洗后删除
2. 同一列混有"万元"和"元" → 统一单位并记日志

### 反馈

发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-biz-report/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。

# lhg-br-metric：指标口径统一

> 目标：让报告里的每个词只有一种意思。
> 核心纪律：**一名一定义**——"营收"在报告里出现 10 次，10 次必须是同一个口径；
> **口径没统一，洞察不许开工**。

## 1. 何时使用

- `/lhg-biz-report:metric-define` → 全流程
- `/lhg-biz-report:biz-report` 第 2 步 → 全流程
- 报告初稿里发现"这个数和那个数打架" → 回到本 skill 查口径
- 用户说"我们内部对这个指标有两种算法" → 跑第 4 节对齐会

## 2. 输入与输出

- **输入**：数据字典（lhg-br-intake 输出）+ 口径问题登记表 + 用户描述
- **输出**：`metrics.json`（见第 3 节格式）+ 口径对齐纪要（冲突项的用户拍板记录）
- **不输出**：分析结论——口径是地基，结论是楼，地基没打好不许盖楼

## 3. metrics.json 字典规范

```json
{
  "version": "1.0.0",
  "metrics": [
    {
      "name": "营收",
      "definition": "主营业务收入，不含税",
      "unit": "万元",
      "period": "2026年Q1-Q3",
      "source": "财务系统",
      "column": "revenue",
      "decimals": 1,
      "formula": ""
    },
    {
      "name": "毛利率",
      "definition": "毛利/营收",
      "unit": "%",
      "period": "2026年Q3",
      "source": "财务系统",
      "column": "",
      "formula": "(营收-成本)/营收"
    }
  ],
  "sum_check": {"total": "revenue", "parts": ["online", "offline"]}
}
```

字段说明：

- `name`：指标名，全局唯一（审计脚本 MET-DUP-001 会查）
- `definition`：一句话定义，必填。写不出一句话定义的指标，不许进报告
- `unit` / `period` / `source`：单位、统计周期、数据来源，必填
- `column`：对应 data.csv 的列名（计算类指标可空）
- `decimals`：保留小数位（审计脚本 CALC-ROUND-001 会查）
- `formula`：比率/占比类指标必填公式（如毛利率）
- `sum_check`：声明"总数=分项和"的校验关系（审计脚本 CALC-SUM-001 会查）
- `version`：口径版本号，口径变了就升版

## 4. 冲突对齐四步法

### 第 1 步：收敛指标名

从数据字典和用户描述里抽出所有指标名，列成清单。
然后找两类冲突：

- **同名不同义**："营收"在财务指含税、在业务指不含税
- **同义不同名**："销售额""营收""GMV"三个人三个叫法，说的是一件事

### 第 2 步：输出对齐清单

每个冲突项给 2–3 个口径选项 + 你的推荐项，格式：

```
冲突：营收（含税 vs 不含税）
选项 A：不含税（财务口径，推荐：和财报对得上）
选项 B：含税（业务口径）
请拍板：
```

### 第 3 步：用户拍板（口径对齐会）

- 一次只对齐有冲突的项，不冲突的不打扰用户
- 拍板结果记入"口径对齐纪要"：谁、什么时候、选了哪个、为什么
- 用户说"都行" → 用推荐项，但纪要里写"用户授权按推荐项"

### 第 4 步：冻结字典

`metrics.json` 写定后，版本号冻结。后续任何人口径想变 → 升版 + 写变更记录，
不许悄悄改 definition。

## 5. 常见口径坑

| 坑 | 例子 | 解法 |
|---|---|---|
| 含税/不含税 | 营收差 13% | definition 写死"含税/不含税" |
| 统计周期 | 自然月 vs 财务月 | period 写清起止 |
| 去重口径 | UV 按天去重 vs 按月去重 | definition 写出去重方式 |
| 退款口径 | GMV 含退款 vs 净收入 | 两个都保留，名字区分开 |
| 汇率口径 | 跨境收入按哪天汇率 | source 里注明 |
| 去重后补录 | 删掉的重复行有没有业务含义 | 删之前问业务方，不许直接删 |

### 口径对齐纪要模板

```markdown
日期：2026-10-11
- 冲突 1「营收含税与否」→ 选 A（不含税，财务口径），拍板人：张三
- 冲突 2「UV 去重方式」→ 按月去重，拍板人：张三
```

## 6. 反模式

1. **口径靠猜**："应该是不含税吧"——猜的口径会在报告里变成事实
2. **同名双定义并存**："这里指 A，那里指 B"——读者只会记住一个，另一个就是误导
3. **字典不冻结**：分析做到一半有人改口径，前面的结论全作废
4. **为省事合并指标**：把"毛利率"和"净利率"混成"利润率"——两个数差几倍，混不得
5. **跳过对齐会**："我先按 A 算，出问题再说"——出问题时重做的是整篇报告

## 7. 自检与反馈

### 质检门（口径交付前自查）

- [ ] `metrics.json` 每个指标五项齐全（定义/单位/周期/来源/小数位）
- [ ] 无同名冲突（`report_audit.py` 的 MET-* 全绿）
- [ ] 冲突项都有用户拍板记录
- [ ] 字典版本号已冻结

### 标准冒烟用例

1. 输入两个"营收"（含税/不含税）→ 输出对齐清单，用户拍板后字典只留一个
2. 毛利率无公式 → MET-FORMULA-001 告警，补公式后通过

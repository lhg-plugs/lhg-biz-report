# lhg-br-insight：洞察提炼

> 目标：把"一堆数字"变成"几句有用的话"。
> 核心纪律：**每个观点必须有数据支撑，每个数据必须标口径**——没有支撑的是观后感，
> 没有口径的是流言。

## 1. 何时使用

- `/lhg-biz-report:biz-report` 第 3 步 → 全流程
- metrics.json 已冻结、data.csv 已就绪 → 开始提炼
- 用户说"数据我都有，就不知道说明了什么" → 直接进本 skill
- 报告初稿被批"全是数字，没有观点" → 按第 3–4 节重做

## 2. 输入与输出

- **输入**：`metrics.json`（已冻结）+ `data.csv`（干净数据）
- **输出**：洞察清单（每条 = 观点一句话 + 支撑数据 + 口径标注），用户确认后再写报告
- **不输出**：报告正文、PPT 页面——那是 lhg-br-deliver 的事

## 3. 四个对比框架（逐项跑，不许跳）

### 框架 1：同比（看趋势）

和去年同期比。回答："这是在变好还是变坏？"

- 算法：（本期 - 去年同期）/ |去年同期|
- 注意基数效应：去年同期基数小，同比 200% 可能只多了几万块——**同时给出绝对值**
- 口径陷阱：两年口径必须一致（lhg-br-metric 已冻结，这里复核一遍）

### 框架 2：环比（看 momentum）

和上一期比。回答："最近是在加速还是减速？"

- 同比向上、环比向下 = 增长但动能减弱——这种"背离"往往是最有价值的洞察
- 季节性提醒：环比受季节影响大，下结论前先看去年同期环比是否同向

### 框架 3：占比（看结构）

谁是大头？回答："钱主要从哪来？"

- 饼图思维：各部分加起来必须是 100%（审计脚本 CALC-PCT-001 会查）
- 结构变化比静态结构更重要："线上占比从 40% 到 60%"比"线上占比 60%"有信息量

### 框架 4：拆解（找功臣和罪人）

把总数拆到渠道 / 产品 / 区域。回答："增长是谁带来的？下滑是谁拖的？"

- 拆解顺序：先拆大头（80/20），小头合并为"其他"
- 反直觉检查：总数增长但主力渠道下滑 → 靠新渠道补的？这种要单独拎出来说

## 4. SO WHAT 三问（每个数字必过）

算出一个数字后，连问三遍：

1. **这个数字说明了什么？**（描述）→ "Q3 营收同比增长 20%"
2. **对业务意味着什么？**（解读）→ "增速连续两季度上行，动能恢复"
3. **不说/不做会怎样？**（行动）→ 不说，管理层不知道该加码线上

三问答不上来 → 这个数字不进洞察清单（它只是数字，不是洞察）。

### 洞察清单格式

```
- 观点：线上渠道成为增长主力，占比从 40% 升至 60%
  支撑：2026Q1 线上 60.0 万 → Q3 72.0 万（+20.0%）；占比 40%→60%
  口径：营收=主营业务收入不含税；周期 2026Q1-Q3；来源财务系统
```

### 洞察分级（清单太长时用）

洞察清单超过 10 条时，按下面分级，报告里只放 P0+P1：

- **P0（必讲）**：影响业务决策的（"线上占比过 60%，建议加码投放"）
- **P1（该讲）**：解释现状的（"线下增速放缓，主因是 X"）
- **P2（备查）**：有趣但暂时用不上的（"周二转化率最高"）——放附录

分级标准：这条洞察能导出一个行动吗？能 → P0；只能解释过去 → P1；
既不能行动也不能解释 → 删掉。

### 交叉验证（四个框架跑完后必做）

四个框架的结论互相打架时，先别急着下结论：

1. **同比向上、环比向下**：增长但动能减弱 → 看绝对值确认量级，再看季节性
2. **总数向上、主力拆解向下**：增长靠新业务补 → 拆出"老业务"和"新业务"两条线单独看
3. **占比上升、绝对值下降**：分母掉得更快 → 这种"虚假繁荣"必须点名
4. **两个数据源打架**：停下来，找业务方确认，不许自己选一边

验证完还解释不通 → 写进"局限与不确定性"，诚实比圆上重要。

交叉验证的记录也要进洞察清单的"备注"栏，方便复核的人跟上你的思路。

记住框架的顺序：先同比环比看方向，再占比拆解找原因——顺序反了，
容易在细节里迷路，忘了回答"到底是变好还是变坏"。

框架是手段，不是目的：跑完四个框架，洞察清单上只留能过 SO WHAT 三问的条目。
清单超过一页纸，就用洞察分级砍到 P0+P1——报告不是越厚越好。

## 5. 数字诚实守则

1. **同比环比一起给**：只给好看的那个 = 挑数据
2. **绝对值相对值一起给**："增长 200%"后面跟上"（从 1 万到 3 万）"
3. **口径变化要声明**："注：Q3 起营收口径调整为不含税，同比按同口径重算"
4. **不确定就写不确定**："样本仅 3 个季度，趋势判断置信度有限"——诚实比漂亮重要
5. **小数位听口径的**：metrics.json 说保留 1 位，报告里不许出现 3 位

## 6. 反模式

1. **数字堆砌**：把表原样搬进报告，一句观点没有——那是数据字典，不是洞察
2. **先射箭后画靶**：心里先有结论，再挑支持它的数据——四个框架跑完，好坏都摆出来
3. **平均数陷阱**："平均增长 15%"——可能是 A 涨 50%、B 跌 20%，拆解了才知道
4. **因果乱下**："因为做了活动，所以涨了"——相关不是因果，没做归因就别写"因为"
5. **洞察清单直接当报告发**：清单是半成品，结论先行的大纲和叙事在 lhg-br-deliver

## 7. 自检与反馈

### 质检门（洞察交付前自查）

- [ ] 四个框架逐项跑过，有记录（不是"心里跑过"）
- [ ] 每条洞察都有支撑数据 + 口径标注
- [ ] 数字经 `lhg-ex-recalc` 思路复算（同比/环比/合计抽查）
- [ ] 用户已确认洞察清单（写报告前必须）

### 标准冒烟用例

1. 输入 Q1–Q3 营收 100/110/120 → 输出同比 +20.0%、环比 +9.1%，附绝对值
2. 输入"增长 200%（基数 1 万）" → 必须同时给出绝对值，不许只报百分比

### 反馈

发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-biz-report/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。
